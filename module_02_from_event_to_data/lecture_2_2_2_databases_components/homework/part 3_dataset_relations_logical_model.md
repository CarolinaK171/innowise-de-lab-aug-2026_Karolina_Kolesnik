# 3. Логическая модель данных

| No | Table Name → Related Table Name | Relationship Type | Relationship Type Description&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; |
| :---: | :--- | :---: | :--- |
| 1 | `cities` → `countries` | `M:1` | Один `country_id` встречается во многих строках `cities`. В одной стране может находиться несколько городов, но каждый город находится только в одной стране. |
| 2 | `products` → `categories` | `M:1` | Один `category_id` встречается во многих строках `products`. К одной категории может принадлежать несколько продуктов, но каждый продукт принадлежит только одной категории. |
| 3 | `shops` → `cities` | `M:1` | Один `city_id` встречается во многих строках `shops`. В одном городе может находиться несколько магазинов, но каждый конкретный магазин находится только в одном городе. |
| 4 | `employees` → `cities`<br><sub>*(через `employees.city_id` — город проживания)*</sub> | `M:1` | Один `city_id` встречается во многих строках `employees`. В одном городе может проживать несколько работников, но каждый конкретный работник проживает только в одном городе. |
| 5 | `employees` → `cities`<br><sub>*(транзитивно через `employees.shop_id` → `shops.city_id` — город работы)*</sub> | `M:1` | Один `shop_id` встречается во многих строках `employees`, а один `city_id` — во многих строках `shops`. В одном городе может работать много сотрудников, но каждый сотрудник работает в одном городе (где находится его магазин). |
| 6 | `customers` → `cities` | `M:1` | Один `city_id` встречается во многих строках `customers`. В одном городе может проживать несколько клиентов, но каждый конкретный клиент проживает только в одном городе. |
| 7 | `sales` → `employees` | `M:1` | Один `employee_id` встречается во многих строках `sales`. Один работник может оформить множество продаж, но каждую конкретную продажу оформляет один работник. |
| 8 | `sales` → `customers` | `M:1` | Один `customer_id` встречается во многих строках `sales`. Один клиент может совершить множество покупок за все время, но каждая конкретная продажа привязана только к одному клиенту. |
| 9 | `sales` → `products` | `M:1` | Один `product_id` встречается во многих строках `sales`. В рамках данного датасета один продукт может иметь множество фактов продаж за все время, но каждая конкретная продажа (строка таблицы `sales`) связана только с одним конкретным продуктом. |
