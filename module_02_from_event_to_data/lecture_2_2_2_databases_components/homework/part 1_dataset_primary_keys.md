# 1\. Primary Keys датасета `source.zip`: описание и обоснование выбора

|No|Table Name|Primary Key|Primary Key Selection Rationale                                                            |
|:-:|-|-|-|
|1|`countries`|`country\\\_id`|Каждой стране назначается свой уникальный номер ID, который однозначно идентифицирует определенную страну и не может повторяться для разных стран|
|2|`cities`|`city\\\_id`|Здесь и далее по аналогии с `countries` из п. 1 — каждому городу назначается свой уникальный номер ID, который однозначно его идентифицирует|
|3|`categories`|`category\\\_id`|Каждой категории соответствует свой уникальный номер ID, который однозначно ее идентифицирует|
|4|`products`|`product\\\_id`|Каждому продукту соответствует свой уникальный номер ID, который однозначно его идентифицирует|
|5|`shops`|`shop\\\_id`|Каждому магазину соответствует свой уникальный номер ID, который однозначно его идентифицирует|
|6|`employees`|`employee\\\_id`|Каждому работнику присваивается свой уникальный номер ID, который однозначно его идентифицирует|
|7|`customers`|`customer\\\_id`|Каждому клиенту присваивается свой уникальный номер ID, который однозначно его идентифицирует|
|8|`sales`|`sales\\\_id`|Каждая строка таблицы `sales` описывает факт продажи конкретного продукта в определенном магазине конкретному покупателю в определенный момент времени и фиксируется в системе с помощью уникального номера ID.<br><br><sub>*Примечание: в качестве альтернативного первичного ключа также может рассматриваться `transaction\\\_number`, который уникальным образом идентифицирует каждую строку / транзакцию в таблице.*</sub>|
